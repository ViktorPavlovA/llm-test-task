# Условия тестового задания, которое предлагает компания ["Союз-Прибор"](https://www.souz-pribor.ru/)

# Тестовое задание

**AI-помощник для подготовки товарных описаний**

Вакансия: AI-разработчик · Ориентировочное время выполнения: 2–4 часа

## 1. Цель задания

Разработать прототип сервиса, который по входным данным о контрольно-измерительном приборе создаёт черновик карточки товара для B2B-интернет-магазина.

Задание проверяет умение работать с LLM API, структурировать технические данные, писать качественные промпты и получать практичный результат для контент-менеджера.

## 2. Входные данные

Кандидату предоставляются данные по двум товарам. Для каждого товара известны:

- Название товара.
- Производитель.
- Краткие характеристики: например, диапазон измерения, класс точности, питание, тип корпуса, интерфейсы.
- Текстовое описание или фрагмент технического паспорта.

### Пример структуры входного JSON

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

## 3. Что должен делать сервис

1. Принимать данные о товаре в формате JSON или через простую веб-форму.
2. Передавать данные в выбранную LLM через API.
3. Формировать черновик карточки товара.
4. Возвращать результат в удобном для копирования виде: JSON, Markdown или текст.
5. Если данных недостаточно, сообщать, какие поля отсутствуют или требуют уточнения.

## 4. Требуемый результат

Для каждого товара сервис должен формировать:

- SEO-заголовок до 70 символов.
- SEO-описание объёмом 800–1 200 символов.
- Структурированный список ключевых характеристик.
- 3–5 поисковых запросов, под которые логично оптимизировать страницу.
- Краткий commercial-блок для менеджера: кому подходит прибор и какие задачи решает.

## 5. Технические требования

- Язык разработки: Python или JavaScript/TypeScript.
- Использование API одной LLM на выбор кандидата: OpenAI, Anthropic, Google, локальная модель или другая доступная модель.
- API-ключ не должен находиться в коде. Используйте переменные окружения или файл конфигурации, добавленный в `.gitignore`.
- Код должен корректно обрабатывать ошибки API, пустые поля и некорректный входной JSON.
- Модель не должна выдумывать характеристики. Все технические значения должны браться только из входных данных.
- Если характеристика отсутствует, в результате должно быть указано: «данных нет» или аналогичная пометка.

## 6. Что необходимо сдать

- Ссылку на Git-репозиторий с кодом.
- README с инструкцией по установке и запуску.
- Пример результата для двух предоставленных товаров.
- Краткое описание использованных промптов и принятых решений.
- Список ограничений решения и возможных улучшений.

## 7. Критерии оценки

Основное внимание уделяется не объёму кода, а качеству и практической применимости решения.

- Корректность, читаемость и структура кода.
- Качество промпта: точность, устойчивость и соответствие задаче.
- Отсутствие выдуманных технических характеристик.
- Обработка неполных или некорректных данных.
- Понятность и готовность результата для контент-менеджера.
- Качество README и простота запуска проекта.

## 8. Ограничения

- Не требуется реализовывать полноценную CMS, админ-панель, базу данных или деплой.
- Не требуется использовать конкретную LLM или векторную базу.
- Достаточно локального прототипа, который можно запустить по инструкции.
- Ориентировочное время выполнения: 2–4 часа. Если задача потребует больше времени, ограничьтесь MVP и опишите, что можно улучшить далее.

**Важно:** не выдумывайте характеристики прибора. Если данных недостаточно, явно укажите это в результате.

## 9. Формат сдачи

Просим прислать:

- Ссылку на репозиторий.
- Короткое сопроводительное сообщение: что реализовано, какие решения приняты, с какими сложностями столкнулись.
- При необходимости — короткую запись экрана или скриншоты результата.
